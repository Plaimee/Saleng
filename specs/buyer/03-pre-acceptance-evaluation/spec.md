## 1. ขอบเขตการทำงาน (Feature Scope)

1. **ดูรายละเอียดคำขอขาย ขนาด รูปถ่าย และสัญลักษณ์ขอคนช่วยยก (`Card 02`, `REQ-FN-003`, `REQ-FN-004`):**
   - เมื่อซาเล้งเลือกดูรายละเอียดงานจากหน้ารายการหรือแผนที่ (Buyer 02) ระบบแสดง:
     - รายการของเก่าทั้งหมดในคำขอ (ประเภทย่อย, ปริมาณ/น้ำหนักประเมิน, และช่วงราคาประเมิน Min-Max)
     - รองรับหมวด `'ของชิ้นใหญ่แบบเหมาจ่าย'` (BULKY_FLAT_RATE เช่น ตู้เย็น, เครื่องซักผ้า 200–500 บาท) และ `'วัสดุบรรจุลังแยกเฉพาะ'` ตาม `REQ-FN-003`
     - รูปถ่ายของเก่าจากผู้ขาย (`photoUrls`) ตาม `REQ-FN-004`
     - ป้ายสัญลักษณ์แจ้งเตือนกรณีผู้ขายขอคนช่วยยกของหนัก (`need_lifting_help`) ตาม `REQ-FN-004`
2. **การประเมินระยะทางและค่าน้ำมันโดยประมาณ (`Distance & Fuel Cost Estimation` — `Card 02`, `REQ-FN-002`, `REQ-QA-002`, `AC-04-11`):**
   - คำนวณระยะทางถนนจริง (`road_distance_km`) จากพิกัดปัจจุบันของซาเล้งไปยังจุดนัดรับของผู้ขาย โดยระยะทางที่แสดงต้องคลาดเคลื่อนจากระยะทางจริงไม่เกิน `15%` (`REQ-QA-002`, `AC-04-11`)
   - คำนวณ **ค่าน้ำมันโดยประมาณ (`estimatedFuelCost`)** ตามประเภทยานพาหนะ (`vehicle_type`) ในโปรไฟล์ซาเล้ง (`Q-01`):
     - รถซาเล้งปั่น (`TRICYCLE`): `0.00 บาท/กม.` (ค่าน้ำมัน = 0 บาท)
     - รถซาเล้งพ่วงข้าง / มอเตอร์ไซค์ (`MOTORCYCLE`): `2.50 บาท/กม.`
     - รถกระบะรับซื้อ (`PICKUP`): `4.50 บาท/กม.`
     - ค่าเริ่มต้น (กรณีไม่ระบุ): `2.50 บาท/กม.`
     - สูตร: `estimated_fuel_cost = round(road_distance_km * fuel_rate_per_km, 2)`
3. **การตรวจสอบและจำกัดความจุรถซาเล้งก่อนรับงาน (`Vehicle Capacity Guard` — `BR-03`, `REQ-CON-003`, `REQ-FN-003`):**
   - ตรวจสอบน้ำหนักสะสมรวม:
     $$\text{projected\_load\_kg} = \text{current\_load\_kg} + \text{job\_est\_weight\_kg}$$
   - เปรียบเทียบกับความจุสูงสุดของรถ (`max_capacity_kg`, ค่าเริ่มต้น 200.0 กก.)
   - **กรณีน้ำหนักรวมไม่เกินความจุ (`projected_load_kg <= max_capacity_kg`):** แสดงแถบความจุสีเขียว/ฟ้า และอนุญาตให้กดรับงานได้
   - **กรณีน้ำหนักรวมเกินความจุ (`projected_load_kg > max_capacity_kg` — `Q-03`, `Q-04`):**
     - แสดงแถบความจุสีแดงแจ้งเตือนอย่างชัดเจน เช่น `"เกินความจุรถ 230/200 กก."`
     - **ปิดการทำงาน (Disable) ของปุ่มกดรับงาน** พร้อมข้อความเตือนให้ซาเล้งนำของในรถไปส่งที่ลานรับซื้อเพื่อเคลียร์รอบวิ่งก่อน (`BR-03`)
4. **การสลับสถานะความพร้อมรับงาน (`Online / Offline Toggle` — `CC-02`, `Q-05`):**
   - ซาเล้งสามารถกดสลับสถานะตัวเองระหว่าง `"พร้อมรับงาน (Online)"` และ `"พักรับงาน (Offline)"`
   - เมื่อสถานะเป็น `Offline`:
     - ซาเล้งยังคงสามารถเปิดดูรายละเอียดงาน ขนาด รูปถ่าย และประเมินค่าน้ำมันได้ตามปกติ
     - แต่ **ปุ่มกดรับงานจะถูกล็อก** พร้อมข้อความแจ้งเตือนให้กดสลับสถานะเป็น `Online` ก่อนจึงจะกดรับงานได้
5. **การคุ้มครองข้อมูลส่วนบุคคลและพิกัดจำลอง (`REQ-SEC-002`, `D-00-02`, `CC-06`):**
   - ในหน้ารายละเอียดการประเมินนี้ คำขอยังอยู่ในสถานะ `S2 (Pending)` (ยังไม่มีการตกลงรับงาน)
   - ระบบจะ **ตัดบ้านเลขที่/ซอย (`addressText`) และเบอร์โทรศัพท์ของผู้ขายทิ้ง 100%**
   - แสดงเฉพาะชื่อระดับ **`ตำบล/แขวง และอำเภอ/เขต`** และพิกัดจำลอง Fuzzed Coordinates (เบี่ยงเบนสุ่ม ±300–500 ม.)
6. **ระบบสำรองระยะทาง Dual-Engine Routing Fallback (`CC-03`, `REQ-OP-002`, `AC-B03-02`):**
   - หากบริการแผนที่ภายนอก (OSRM / Maps API) ไม่ตอบสนองภายใน 1.5–2.0 วินาที ระบบจะสลับไปใช้สูตรสำรอง **`Haversine * 1.35`** ทันที พร้อมแสดงป้าย `"⚡ ระยะทางประเมินสำรอง"` (`is_fallback: true`) ตาม `CC-03` เพื่อให้ซาเล้งประเมินงานต่อได้กลางแดด
7. **การบูรณาการกับกฎเหล็ก Unverified Collector Claim Gate (`D-00-01`, `Q-06`):**
   - ซาเล้งที่ยังไม่ผ่าน KYC (`verified = false`) สามารถเปิดดูรายละเอียดงานและประเมินค่าน้ำมันได้
   - แต่ **ปุ่มกดรับงานจะล็อกด้วยรูปแม่กุญแจ 🔒** เมื่อกดจะแสดง Informative Gate Modal แจ้งเตือนสิทธิ์และมีปุ่มนำทางไปหน้า KYC

## 2. สิ่งที่อยู่นอกขอบเขต (Non-goals / Out of Scope)

- **การกดรับงานและผูกใบงานจริง (`Order Claiming & Optimistic Locking`):** เป็นขอบเขตของ `specs/buyer/04-job-and-route-management/` (`UC-04`) ฟีเจอร์นี้ทำหน้าที่ประเมินและตรวจสอบความถูกต้องก่อนกดรับงาน
- **การนำทางแบบเลี้ยวต่อเลี้ยว (Turn-by-turn Navigation):** เกิดขึ้นหลังจากกดรับงานแล้วใน Buyer 04
- **การเปิดเผยบ้านเลขที่จริงและเบอร์โทรศัพท์:** จะเปิดเผยให้เฉพาะซาเล้งที่กดรับงานสำเร็จแล้วในสถานะ `S3 (Assigned)` ตามกฎ `REQ-SEC-002` และ `D-00-02`
- **การยืนยันตัวตน KYC:** จัดการใน `specs/buyer/01-account-and-kyc/`
- **การชั่งน้ำหนักจริงและการออกใบเสร็จดิจิทัล:** จัดการใน Buyer 05 และ Buyer 06

## 4. ข้อสรุปการตัดสินใจจากการ Clarify (`Q-01` ถึง `Q-06` / `D-B03-01` ถึง `D-B03-06`)

- **`D-B03-01` (สูตรค่าน้ำมันตามประเภทยานพาหนะ — `Q-01`):** คำนวณค่าน้ำมันจาก `road_distance_km * fuel_rate` โดยอิงตาม `vehicle_type` ของซาเล้ง: รถปั่น = 0.00 บาท/กม., มอเตอร์ไซค์พ่วงข้าง = 2.50 บาท/กม., รถกระบะ = 4.50 บาท/กม. (Default = 2.50 บาท/กม.)
- **`D-B03-02` (Dual-Engine Routing Fallback — `Q-02`):** ยึดตาม `CC-03` และ `REQ-OP-002` โดยสลับใช้สูตร `Haversine * 1.35` อัตโนมัติเมื่อบริการแผนที่ภายนอกช้ากว่า 1.5 วินาที พร้อมแสดงป้ายโหมดสำรอง
- **`D-B03-03` (การสะสมน้ำหนักตรวจความจุรถ — `Q-03`):** นำน้ำหนักปัจจุบันในรถ (`current_load_kg`) + น้ำหนักประเมินของงานใหม่ เทียบกับ `max_capacity_kg` เพื่อให้จัดสรรพื้นที่รถได้ถูกต้อง 100% ตาม `BR-03`
- **`D-B03-04` (การบล็อกปุ่มรับงานเมื่อเกินความจุ — `Q-04`):** หากน้ำหนักรวมเกิน `max_capacity_kg` ให้เปลี่ยนแถบความจุเป็นสีแดง และ **Disable ปุ่มกดรับงาน** พร้อมแจ้งเตือนให้เคลียร์รอบวิ่งก่อน
- **`D-B03-05` (สถานะ Offline — `Q-05`):** ซาเล้งสถานะ Offline สามารถเปิดดูรายละเอียดและประเมินงานได้ แต่ปุ่มรับงานจะล็อกพร้อมข้อความเตือนให้สลับเป็น Online ก่อน
- **`D-B03-06` (Unverified KYC Gate — `Q-06`):** ซาเล้งที่ยังไม่ผ่าน KYC สามารถดูรายละเอียดงานได้ แต่ปุ่มรับงานจะล็อกด้วยแม่กุญแจ และมี Modal นำทางไปยื่นเอกสาร KYC ตามกฎ `D-00-01`

## 5. ตารางตรวจสอบความสอดคล้องกับ Constraints กลางครบทั้ง 13 ข้อ

| :---: | :--- | :--- | :---: |
| **`CC-01`** | Mobile-First Web SPA รองรับมือถือราคาประหยัด (`RAM >= 2 GB`, ปุ่ม `>= 48px`) | หน้ารายละเอียดงานและปุ่มกดรับงานมีขนาดความสูงไม่น้อยกว่า `48px` (`REQ-UX-001`) แสดงผลชัดเจนกลางแดดจ้า | **ครบถ้วน** |
| **`CC-02`** | GPS Sync Interval ทุก 60 วินาทีขณะเปิดสถานะ Online | รองรับสลับสถานะ Online/Offline โดยเมื่อ Online จะซิงก์พิกัดและคำนวณระยะทางรอบละ 60 วินาที (`AC-B03-03`) | **ครบถ้วน** |
| **`CC-03`** | Road Distance API รัศมี `<= 5.0 กม.` พร้อม Haversine Fallback (`Haversine * 1.35`) | ใช้ Dual-Engine Routing คำนวณระยะทางถนนจริง และสลับใช้ `Haversine * 1.35` ทันทีเมื่อ API ล้มเหลว (`AC-B03-02`, `D-B03-02`) | **ครบถ้วน** |
| **`CC-04`** | PostgreSQL + Concurrency Control / Optimistic Locking (`BR-02`) | ตรวจสอบสถานะคำขอ `S2 (Pending)` และความถูกต้องของข้อมูลผ่าน In-memory SupabaseStore / PostgreSQL | **ครบถ้วน** |
| **`CC-05`** | Offline Cache ใน IndexedDB / Local Storage | แคชข้อมูลรายละเอียดคำขอขายล่าสุดใน `localStorage` ให้เปิดดูได้แม้ออฟไลน์ (`REQ-OP-001`) | **ครบถ้วน** |
| **`CC-06`** | PDPA & PII Masking ซ่อนบ้านเลขที่และพิกัดละเอียด | ตัดบ้านเลขที่ทิ้ง แสดงเฉพาะชื่อตำบล/แขวง และใช้พิกัดจำลอง Fuzzed Coordinates (±300–500 ม.) (`AC-B03-04`, `REQ-SEC-002`) | **ครบถ้วน** |
| **`REQ-SEC-001`** | บันทึกประวัติลงตาราง Audit Log | ทุกการเปิดประเมินงานและสลับสถานะ Online/Offline ถูกบันทึกลงใน `audit_logs` | **ครบถ้วน** |
