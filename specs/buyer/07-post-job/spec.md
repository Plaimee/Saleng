# ฝั่งผู้ซื้อ (ซาเล้ง) ลำดับที่ 7: ระบบหลังจบงาน (`7. ระบบหลังจบงาน`)

- **Version:** `2.0` | **Status:** `reviewed-post-clarify` | **Owner:** กลุ่ม 2 (แพลตฟอร์มรับซื้อของเก่า/ซาเล้ง)
- **อ้างอิงอาร์ติแฟกต์ที่เกี่ยวข้อง:**
  - ตารางแบ่งฟีเจอร์ฝั่ง **`ผู้ซื้อ`** ลำดับที่ **`7`**
  - Use Case กลาง: **`UC-10: ให้คะแนนรีวิว สรุปยอดรายวัน และจัดการหลังจบงาน`** ([`docs/srs/use-cases.md`](../../../docs/srs/use-cases.md))
  - Use Case ร่วม: **`UC-13: ตัดสินข้อพิพาทและงานตกค้าง`** ([`docs/srs/use-cases.md`](../../../docs/srs/use-cases.md))
  - State Machine กลาง: **`MD-STM-04`** สถานะ **`S7 (Completed)`** และ **`S8 (Disputed)`** ([`specs/002-route/models.md`](../../002-route/models.md))
  - พฤติกรรมซาเล้งจากการสัมภาษณ์: การเก็บพิกัดลูกค้าประจำ และการจัดการกรณีไปถึงหน้าบ้านแล้วของจริงไม่ตรงกับที่แจ้ง หรือลูกค้าไม่อยู่บ้าน `No-show` (SRS หน้า 28, 32)
  - ความต้องการที่เกี่ยวข้อง:
    - **`UC-10`**: ดูประวัติการรับซื้อย้อนหลัง สรุปยอดสะสมรายวัน/รายเดือน และปักหมุดลูกค้าประจำ
    - **`UC-13` / `REQ-FN-006`**: รายงานข้อพิพาทกรณีผู้ขายไม่อยู่บ้าน (`No-show`) หรือของเก่าไม่ตรงกับที่แจ้งไว้มาก พร้อมแนบภาพถ่ายหลักฐานส่งให้ Admin
    - **`REQ-FN-005`**: เปิดดูและตรวจสอบใบเสร็จดิจิทัล (`DigitalReceipt`) ในประวัติการรับซื้อย้อนหลัง
    - **`REQ-SEC-001`**: บันทึกประวัติการกระทำ (ส่งรายงานข้อพิพาท, ปักหมุด/ยกเลิกลูกค้าประจำ) ลงในตาราง `AuditLog`
    - **`REQ-SEC-002` / `CC-06`**: ปกปิดเบอร์โทรศัพท์เป็น `08X-XXX-XXXX` และซ่อนบ้านเลขที่/พิกัดละเอียดหลังจบงานเกิน 24 ชั่วโมง (`S7`) ตามกฎหมาย PDPA
    - **`REQ-OP-001` / `CC-05`**: โหมด Offline Cache สำหรับเปิดดูประวัติและใบเสร็จดิจิทัลย้อนหลังที่แคชไว้ใน Local Storage
    - **`REQ-UX-001` / `CC-01`**: ออกแบบหน้าจอ Mobile-First รองรับสมาร์ตโฟนราคาประหยัด พร้อมทัชทาร์เก็ตปุ่มกดขนาดใหญ่ `>= 48px`

> [!NOTE]
> **ความสอดคล้องกับสารบัญกลางและสถาปัตยกรรมระบบ (`CC-01`, `CC-02`, `CC-03`):**
> 1. **`CC-01` (Use Case ID):** ปรับรหัส Use Case ให้ถูกต้องตามสารบัญกลาง ([`use-cases.md`](../../../docs/srs/use-cases.md)) โดยเชื่อมโยงกับ **`UC-10`** (ระบบหลังจบงานของซาเล้งและผู้ขาย) และ **`UC-13`** (การส่งรายงานข้อพิพาทเข้าคิว Admin)
> 2. **`CC-02` (State Machine Transitions):** การรายงานผู้ขายกรณี No-show หรือของไม่ตรงสเปกจากสถานะ `S3` หรือ `S4` จะเปลี่ยนสถานะคำขอเป็น **`S8: Disputed`** (`Q-01`, `Q-02`) เพื่อส่งให้ Admin ตรวจสอบ และปลดล็อกซาเล้งให้สามารถรับงานถัดไปในคิวได้
> 3. **`CC-03` (PDPA & Bookmark Data Structure):** การปักหมุด "ลูกค้าประจำ" (`Q-03`) จะจัดเก็บพิกัด Latitude/Longitude, ชื่อผู้ขาย/ป้ายกำกับ, และบันทึกย่อส่วนตัว โดยไม่เปิดเผยบ้านเลขที่หรือเบอร์โทรศัพท์ที่ไม่ Mask หลังจบงานเกิน 24 ชม.

## 1. ขอบเขตการทำงาน (Feature Scope)

1. **ดูประวัติการรับซื้อของเก่าย้อนหลังและสถิติสะสม (`UC-10`, `REQ-FN-005`, `REQ-SEC-002`, `Q-05`):**
   - **สถิติสรุปสะสม (Aggregated Summary Cards):**
     1. รายจ่ายค่าซื้อของเก่ารวม (บาท)
     2. น้ำหนักวัสดุรับซื้อรวมสะสม (กก.)
     3. จำนวนงานที่รับซื้อสำเร็จ (ครั้ง/งาน)
     - มีตัวกรองเลือกดูตามช่วงเวลา: ทั้งหมด (All-time), รายวัน (Today), และ รายเดือน (This Month)
   - **รายการประวัติการรับซื้อย้อนหลัง (Purchase History Cards / List):**
     - วันที่และเวลาที่จบงานสำเร็จ (`issued_at` / `completed_at`)
     - รหัสคำขอขาย (`order_id`)
     - รายการของเก่าที่รับซื้อ (ชนิดวัสดุ, น้ำหนักจริง, ราคาต่อหน่วยที่ล็อกไว้)
     - ยอดเงินสุทธิที่จ่าย (บาท)
     - ช่องทางชำระเงิน (`CASH` หรือ `PROMPTPAY`)
     - ชื่อผู้ขาย และเบอร์โทรศัพท์ที่ถูกปกปิดตามมาตรฐาน PDPA (`08X-XXX-XXXX` ตาม `REQ-SEC-002`)
     - ป้ายสถานะ `S7: สำเร็จ / ปิดงานเรียบร้อย`
     - ปุ่มกดเพื่อเปิดดูใบเสร็จดิจิทัลฉบับเต็ม (`DigitalReceiptModal`)
     - ปุ่มกดปักหมุด "บันทึกลูกค้าประจำ" (`Regular Customer Bookmark`)

2. **บันทึกพิกัดและบันทึกย่อลูกค้าประจำ (`UC-10`, `REQ-SEC-001`, `REQ-SEC-002`, `Q-03`, `Q-04`):**
   - ซาเล้งสามารถกดปักหมุดบันทึกบ้านผู้ขายที่ขายของเก่าสม่ำเสมอไว้ในรายการ **`"ลูกค้าประจำ"`** (`collector_favorite_sellers`) หลังจบงาน (`S7`) หรือจากหน้ารายละเอียดประวัติย้อนหลัง
   - **ข้อมูลที่จัดเก็บ:**
     - `collector_id`, `seller_id`, พิกัดจุดรับซื้อ (`latitude`, `longitude`)
     - ป้ายชื่อลูกค้าประจำ / ชื่อผู้ขาย
     - บันทึกย่อส่วนตัวของซาเล้ง (Notes เช่น *"บ้านรั้วสีฟ้า สะดวกเสาร์-อาทิตย์", "มีทองแดงและแบตเตอรี่บ่อย"*) ความยาวไม่เกิน 200 ตัวอักษร
     - เบอร์โทรศัพท์ที่ Mask แล้ว (`08X-XXX-XXXX`)
   - **การจัดการรายการลูกค้าประจำ:**
     - หน้ารวมรายชื่อลูกค้าประจำ พร้อมพิกัดและบันทึกย่อ
     - รองรับการสลับสถานะ (Toggle Bookmark: เพิ่มเข้า / ยกเลิกออก)
     - ซาเล้งไม่มีการให้คะแนนดาว (Rating 1–5 ดาว) ผู้ขาย (`Q-04`) แต่ใช้ระบบ Bookmark นี้เพื่อวางแผนเส้นทางวิ่งรถในรอบสัปดาห์ถัดไป

3. **รายงานผู้ขายกรณีข้อมูลไม่ตรง / ไม่อยู่บ้าน No-Show (`UC-13`, `REQ-FN-006`, `REQ-SEC-001`, `Q-01`, `Q-02`):**
   - เมื่อซาเล้งเดินทางไปถึงหน้างานแล้วพบปัญหาที่ไม่สามารถดำเนินการรับซื้อต่อได้:
     1. **ผู้ขายไม่อยู่บ้านตามนัด (`No-show`):** เดินทางไปถึงจุดนัดหมายในสถานะ `S3: En Route` แล้วติดต่อผู้ขายไม่ได้ เกินเวลาที่กำหนด
     2. **ข้อมูลของเก่าไม่ตรงกับที่แจ้งไว้มาก (`Mismatch / Contamination`):** ตรวจสอบของเก่าในสถานะ `S4: Weighing` แล้วพบว่ามีสิ่งปนเปื้อนอันตราย, ปริมาณน้อยกว่าเกณฑ์ขั้นต่ำมากและผู้ขายไม่ยอมรับ, หรือของจริงไม่ตรงกับที่แจ้งอย่างสิ้นเชิง
   - **การส่งรายงานข้อพิพาท:**
     - ซาเล้งกดปุ่ม *"รายงานปัญหาหน้างาน / แจ้งข้อพิพาท"*
     - เลือกสาเหตุของปัญหา (`mismatch_reason`: `SELLER_NO_SHOW`, `CONTAMINATED_WASTE`, `QUANTITY_MISMATCH`, `OTHER`)
     - บังคับแนบภาพถ่ายหน้างานเป็นหลักฐาน (`evidence_photo_url` เช่น ภาพหน้าบ้านที่ปิดเงียบ หรือภาพกองของเก่าที่ปนเปื้อน)
     - บันทึกพิกัด GPS ขณะกดรายงานเพื่อยืนยันว่าซาเล้งเดินทางไปถึงหน้างานจริง
     - ระบุรายละเอียดเพิ่มเติม (ข้อความอธิบายเหตุการณ์)
   - **ผลลัพธ์ของระบบ:**
     - อัปเดตสถานะคำขอเป็น **`S8: Disputed`** ทันที เพื่อส่งเรื่องเข้าศูนย์ควบคุมข้อพิพาทของ Admin (`UC-13`, `Q-01`)
     - ปลดล็อกซาเล้งออกจากงานนี้ทันที เพื่อให้สามารถเดินทางไปรับงานถัดไปในคิวเส้นทางได้โดยไม่ถูกบล็อก
     - บันทึกประวัติการรายงานลงใน Audit Log (`REQ-SEC-001`)

4. **การเข้าถึงใบเสร็จดิจิทัลและรองรับโหมดออฟไลน์ (`CC-05`, `REQ-OP-001`):**
   - ซาเล้งสามารถเปิดดูใบเสร็จดิจิทัลฉบับสมบูรณ์ของคำขอย้อนหลังได้ตลอดเวลา
   - ข้อมูลประวัติการรับซื้อและใบเสร็จดิจิทัลที่เคยเปิดแล้ว จะถูกแคชลงใน Local Storage เพื่อให้สามารถเปิดดูได้แม้อยู่ในจุดอับสัญญาณ

> [!NOTE]
> **ขอบเขตและสิ่งที่จงใจไม่ทำ (Non-goals — `Q-06`):**
> 1. **ไม่ทำระบบแชทติดต่อต่อหลังจบงาน (`S7`):** ปิดช่องทางการสื่อสารเมื่อจบงาน เพื่อรักษาความเป็นส่วนตัวตาม `REQ-SEC-002`
> 2. **ไม่ทำระบบจ่ายเงินชดเชยค่าเดินทางอัตโนมัติเมื่อเกิดข้อพิพาท:** การพิจารณาค่าชดเชยน้ำมันหรือบทลงโทษผู้ขายอยู่ในดุลยพินิจของ Admin ตาม `UC-13` และ `UC-11`
> 3. **ไม่เปิดเผยเบอร์โทรศัพท์จริงหรือพิกัดที่อยู่อาศัยที่ไม่ได้ Mask ในประวัติย้อนหลังเกิน 24 ชั่วโมง:** เพื่อให้สอดคล้องกับกฎหมาย PDPA อย่างเคร่งครัด
> 4. **ไม่ทำระบบให้คะแนนดาว (1–5 ดาว) แก่ผู้ขาย:** การประเมินคู่ค้าฝั่งซาเล้งใช้ระบบ Bookmark ลูกค้าประจำและการรายงานข้อพิพาทเท่านั้น (`Q-04`)

## 2. เกณฑ์การยอมรับ (`Acceptance Criteria`)

- **`AC-B07-01` (Purchase History Log & Aggregated Stats — `UC-10`, `REQ-FN-005`, `REQ-SEC-002`, `Q-05`):**
  - ซาเล้งสามารถเข้าดูหน้ารวมประวัติการรับซื้อย้อนหลัง ซึ่งแสดงสถิติสรุปสะสม 3 มิติ (ยอดจ่ายรวม, น้ำหนักรวม, จำนวนงานสำเร็จ) พร้อมตัวกรองรายวัน/รายเดือน และรายการคำขอสถานะ `S7` โดยเบอร์โทรศัพท์ของผู้ขายถูก Mask เป็น `08X-XXX-XXXX`
- **`AC-B07-02` (Regular Customer Bookmark & Notes — `UC-10`, `REQ-SEC-001`, `REQ-SEC-002`, `Q-03`, `Q-04`):**
  - ซาเล้งสามารถกดปุ่มปักหมุดบันทึกหรือยกเลิกผู้ขายเป็น `"ลูกค้าประจำ"` (`collector_favorite_sellers`) พร้อมระบุบันทึกย่อส่วนตัว (ไม่เกิน 200 ตัวอักษร) ได้จากหน้ารายละเอียดคำขอหรือหน้าประวัติ และสามารถดูรายการลูกค้าประจำทั้งหมดพร้อมพิกัดนำทางได้
- **`AC-B07-03` (Seller Mismatch & No-Show Dispute Report — `UC-13`, `REQ-FN-006`, `REQ-SEC-001`, `Q-01`, `Q-02`):**
  - ในสถานะ `S3` (En Route) หรือ `S4` (Weighing) ซาเล้งสามารถกดรายงานผู้ขายกรณี No-show หรือของไม่ตรงสเปก โดยบังคับแนบรูปถ่ายหลักฐานหน้างาน (`evidence_photo_url`) และระบุสาเหตุ ระบบจะเปลี่ยนสถานะคำขอเป็น `S8: Disputed` ส่งเรื่องให้ Admin ตรวจสอบ และปลดล็อกซาเล้งให้รับงานถัดไปได้ทันที
- **`AC-B07-04` (Digital Receipt Inspection & Offline Access — `REQ-FN-005`, `REQ-OP-001`, `CC-05`):**
  - ซาเล้งสามารถเปิดดูใบเสร็จดิจิทัลฉบับสมบูรณ์จากรายการประวัติย้อนหลังได้ และสามารถเปิดดูใบเสร็จรวมถึงรายการประวัติที่เคยแคชไว้ได้แม้อยู่ในโหมดออฟไลน์
- **`AC-B07-05` (Audit Logging & Data Integrity — `REQ-SEC-001`):**
  - ทุกการส่งรายงานข้อพิพาท (`COLLECTOR_REPORTED_MISMATCH`) และการเพิ่ม/ลบลูกค้าประจำ (`COLLECTOR_BOOKMARKED_CUSTOMER`) ต้องบันทึกประวัติลงใน `AuditLog` พร้อมเวลาประทับ พิกัด และรหัสผู้กระทำอย่างครบถ้วน
