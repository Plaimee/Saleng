## 1. ขอบเขตการทำงาน (Feature Scope)

1. **การกดรับงานแบบ Atomic Claim & Single Collector Lock (`BR-02`, `REQ-BR-002`, `CC-04`, `D-B04-01`):**
   - ซาเล้งที่ผ่านการตรวจสอบเงื่อนไขจาก Buyer 03 แล้ว (ผ่าน KYC `verified = true`, สถานะ `Online`, และน้ำหนักรวมไม่เกินความจุรถ `200 กก.`) สามารถกดปุ่ม **`"กดรับงานนี้"`** ในหน้าประเมินงาน
   - **กลไกป้องกันการรับงานซ้ำซ้อน (Atomic Concurrency Control):**
     - ใช้กลไก `Optimistic Concurrency Control (OCC)` ผ่านฐานข้อมูล PostgreSQL ด้วยเงื่อนไข:
       ```sql
       UPDATE orders 
       SET status = 'S3', collector_id = :saleng_id, version = version + 1, updated_at = NOW() 
       WHERE id = :order_id AND status = 'S2' AND version = :expected_version;
       ```
     - หากมีซาเล้ง 2 คนกดรับงานเดียวกันพร้อมกัน ซาเล้งคนแรกที่ระบบประมวลผลสำเร็จจะได้งานไป (สถานะเปลี่ยนเป็น `S3: มีผู้รับงานแล้ว` ผูกกับ `saleng_id`)
     - ซาเล้งคนที่สองจะได้รับข้อความแจ้งเตือนทันทีว่า `"มีผู้รับงานนี้แล้ว"` (HTTP `409 Conflict`) และระบบจะนำทางกลับไปยังหน้ารายการค้นหางานพร้อมรีเฟรชข้อมูลอัตโนมัติ
2. **การข้ามงาน / สละสิทธิ์ก่อนรับ (`Extension A2`):**
   - ในหน้ารายละเอียดการประเมิน ซาเล้งสามารถกดปุ่ม **`"ข้ามงานนี้"`** หรือปุ่มย้อนกลับ
   - ระบบจะปิดหน้ารายละเอียดและกลับไปยังหน้ารายการงาน โดยที่คำขอขายนั้นยังคงอยู่ในสถานะ `S2: รอผู้รับงาน` ตามเดิม เพื่อเปิดโอกาสให้ซาเล้งคนอื่นในพื้นที่สามารถมองเห็นและรับงานได้
3. **การเปิดเผยบ้านเลขที่จริงและพิกัดแท้จริงเฉพาะผู้รับงาน (`Address & Coordinate Unmasking` — `REQ-SEC-002`, `D-00-02`, `CC-06`):**
   - เมื่อการกดรับงานสำเร็จเข้าสู่สถานะ `S3 (Assigned)` ระบบจะ **ปลดล็อกและเปิดเผยข้อมูลส่วนบุคคล (PII)** ให้เฉพาะซาเล้งที่ได้รับงานคนนั้นเท่านั้น:
     - บ้านเลขที่และชื่อซอยฉบับเต็ม (`address_text` เช่น `"123/45 ซอยประชาราษฎร์บำเพ็ญ 24"`)
     - พิกัดจริงระดับละติจูด/ลองจิจูดแท้จริง (`dest_lat`, `dest_lng`)
     - เบอร์โทรศัพท์ของผู้ขายสำหรับติดต่อหน้างาน
   - ซาเล้งคนอื่นที่ไม่ได้งานจะยังคงเห็นเฉพาะพิกัดจำลอง Fuzzed Coordinates และชื่อตำบล/แขวงตามกฎ PDPA
4. **การจัดการคิวงานและตารางนัดหมายสะสม (`Active Queue & Schedule Management` — `BR-03`, `D-B04-02`):**
   - แสดงหน้ารวมตารางงานที่ซาเล้งกดรับไว้แล้ว (`Active Job Queue`) ซึ่งอยู่ในสถานะ `S3 (มีผู้รับงานแล้ว)` และ `S4 (กำลังเดินทาง)`
   - แสดงน้ำหนักบรรทุกสะสมรวมของคิวงานทั้งหมดเทียบกับความจุสูงสุดของรถ (`current_load_kg / 200.0 กก.`)
   - แสดงรายละเอียดเวลานัดหมาย (`slot_time`), ประเภทขยะ, และราคาประเมิน
5. **การจัดลำดับจุดแวะรับตามเส้นทางอย่างคุ้มค่า (`Route Optimization` — `D-B04-02`):**
   - ระบบช่วยจัดเรียงลำดับจุดแวะรับขยะในคิวงานของซาเล้ง โดยอิงจาก:
     1. ช่วงเวลานัดหมายของผู้ขาย (`pickup_slot_time`)
     2. ลำดับระยะทางที่ใกล้ที่สุดจากตำแหน่งปัจจุบัน (Greedy Nearest-Neighbor Sorting)
   - แสดงระยะทางรวมและเวลาที่คาดว่าจะถึง (ETA) ของแต่ละจุดแวะรับ
6. **การออกเดินทางและระบบนำทาง GPS (`In-Transit & Navigation Launch` — `UC-09`, `D-B04-03`):**
   - เมื่อซาเล้งพร้อมออกเดินทางไปยังจุดนัดรับ ซาเล้งกดปุ่ม **`"เริ่มออกเดินทาง"`**
   - ระบบเปลี่ยนสถานะใบงานจาก `S3 (มีผู้รับงานแล้ว)` เป็น **`S4 (กำลังเดินทาง / In-Transit)`**
   - **กฎการล็อกสิทธิ์ยกเลิกของผู้ขาย (`BR-03`):** เมื่อเข้าสู่สถานะ `S4` ระบบจะปิดการทำงาน (Disable) ของปุ่มยกเลิกฝั่งผู้ขายทันที เพื่อไม่ให้ซาเล้งต้องเสียเที่ยวเดินทาง
   - **การเปิดระบบนำทาง GPS:** ระบบเชื่อมต่อกับแอปแผนที่นำทางภายนอกของสมาร์ตโฟน (Google Maps / Apple Maps) ผ่าน URL Scheme มาตรฐาน:
     `https://www.google.com/maps/dir/?api=1&destination={dest_lat},{dest_lng}`
     (โดยไม่สร้างระบบ Turn-by-Turn ภายในเว็บแอปตาม Non-goals ของ `SPEC-ROUTE`)
7. **การยกเลิกงานและคืนสถานะคำขอ (`Collector Cancellation & Reversion` — `D-B04-04`, `MD-STM-04`):**
   - หากเกิดเหตุสุดวิสัยในสถานะ `S3 (Assigned)` เช่น รถเสีย กะทันหัน หรือมีเหตุฉุกเฉิน ซาเล้งสามารถกดยกเลิกงานได้พร้อมเลือก/กรอกเหตุผล:
     - `VEHICLE_BREAKDOWN` (รถเสีย/ยางแตก/เครื่องยนต์ขัดข้อง)
     - `ACCIDENT` (เกิดอุบัติเหตุระหว่างทาง)
     - `PERSONAL_EMERGENCY` (เหตุฉุกเฉินส่วนตัว)
     - `OTHER` (อื่น ๆ พร้อมคำอธิบาย)
   - **ผลของการยกเลิกในสถานะ `S3`:**
     - ระบบจะ **คืนสถานะคำขอขายกลับเป็น `S2 (Pending)` โดยอัตโนมัติ** เพื่อให้คำขอขายกลับไปปรากฏในกระดานค้นหางานของซาเล้งคนอื่นในพื้นที่ทันที โดยที่ผู้ขายไม่ต้องเสียเวลาสร้างโพสต์ใหม่
     - ล้างการผูกมัด `collector_id = None`
     - บันทึกประวัติการยกเลิกลงใน `audit_logs` (`actor_id = saleng_id, action = 'COLLECTOR_CANCELLED_JOB', reason = ...`)
   - หากสถานะเป็น `S4 (In-Transit)` แล้ว: ซาเล้งสามารถกดยกเลิกได้เฉพาะเหตุฉุกเฉินระดับสูงเท่านั้น พร้อมส่งแจ้งเตือนด่วนไปยังผู้ขายและระบบศูนย์กลาง
8. **การแจ้งเตือนข้อมูลซาเล้งไปยังผู้ขายทันทีเมื่อรับงาน (`Seller Notification & Collector Binding` — `D-B04-05`):**
   - เมื่อการรับงานสำเร็จ (`S2 -> S3`) ระบบส่ง Event แจ้งเตือนไปยังหน้าจอติดตามของผู้ขาย (`specs/seller/05-booking-and-status-tracking`) ทันที พร้อมแนบข้อมูลโปรไฟล์ซาเล้ง:
     - ชื่อซาเล้ง (`display_name`)
     - เบอร์โทรศัพท์สำหรับติดต่อ (`phone`)
     - ประเภทรถและป้ายทะเบียน (`vehicle_type`, `license_plate`)
     - รูปโปรไฟล์และคะแนนดาวรีวิว (`avatar_url`, `rating`)
9. **การทำงานและแคชตารางนัดหมายในโหมดออฟไลน์ (`Offline Schedule Cache & Queue` — `REQ-OP-001`, `CC-05`, `D-B04-06`):**
   - บันทึกรายการงานที่ซาเล้งรับแล้วลงใน `localStorage` / `IndexedDB` (`saleng_active_schedule_cache`)
   - เมื่ออยู่ในจุดอับสัญญาณอินเทอร์เน็ต:
     - ซาเล้งยังสามารถเปิดดูรายการนัดหมาย บ้านเลขที่ผู้ขาย และเบอร์โทรที่บันทึกไว้ล่าสุดได้ พร้อมแสดงป้ายแจ้งเตือน `"ข้อมูลอาจไม่อัปเดต (โหมดออฟไลน์)"`
     - ซาเล้งสามารถกดปุ่มนำทาง GPS (ซึ่งทำงานผ่าน GPS ชิปของมือถือ) ได้ตามปกติ
     - การกดเปลี่ยนสถานะเป็น `S4` ขณะออฟไลน์ จะถูกบันทึกเข้า `Offline Queue` พร้อม `idempotency_key` และซิงก์อัปเดตอัตโนมัติทันทีที่สัญญาณกลับมา

## 4. ข้อสรุปการตัดสินใจจากการ Clarify (`D-B04-01` ถึง `D-B04-06`)

- **`D-B04-01` (Concurrency Control ด้วย PostgreSQL OCC — `Q-01`):** ใช้ `Optimistic Concurrency Control (OCC)` ผ่านฟิลด์ `version` ในฐานข้อมูล PostgreSQL/SupabaseStore ตาม `CC-04` และ `BR-02` ตัด Redis Lock ออกจากสเปกเพื่อความสอดคล้องกับข้อจำกัดกลาง
- **`D-B04-02` (การจัดการคิวงานสะสมและ Route Ordering — `Q-02`):** ซาเล้งสามารถรับงานสะสมในสถานะ `S3` ได้ตราบใดที่น้ำหนักรวมไม่เกินความจุรถสูงสุด `200 กก.` (`BR-03`) โดยระบบจัดลำดับจุดแวะรับตามเวลานัดหมายและระยะทางใกล้เคียง (Nearest-Neighbor)
- **`D-B04-03` (การเชื่อมต่อระบบนำทาง GPS ผ่าน URL Scheme — `Q-03`):** สำหรับ Mobile-First Web SPA ระบบจะเรียกเปิดแอปนำทางภายนอก (Google Maps / Apple Maps) ผ่าน URL Scheme `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}` แทนการทำ Turn-by-turn ในเว็บแอป
- **`D-B04-04` (การยกเลิกงานและคืนสถานะคำขอ — `Q-04`):** เมื่อซาเล้งกดยกเลิกงานในสถานะ `S3` ระบบจะคืนสถานะคำขอขายกลับเป็น `S2 (Pending)` โดยอัตโนมัติ เพื่อให้ซาเล้งคนอื่นรับต่อได้ทันที และบันทึกประวัติลง `audit_logs`
- **`D-B04-05` (การผูกข้อมูลซาเล้งส่งให้ผู้ขาย — `Q-05`):** เมื่อรับงานสำเร็จ ระบบจะผูกข้อมูลซาเล้ง (`display_name`, `phone`, `vehicle_type`, `license_plate`, `avatar_url`, `rating`) และส่งให้ผู้ขายแสดงผลในการ์ดติดตามทันที
- **`D-B04-06` (การแคชตารางงานและคิวออฟไลน์ — `Q-06`):** จัดเก็บตารางงานที่รับแล้วลงใน `localStorage` ให้เปิดดูที่อยู่และเบอร์โทรได้แม้ออฟไลน์ และจัดเก็บคำขอเปลี่ยนสถานะใน `Offline Queue` พร้อม `idempotency_key` เพื่อส่งซิงก์เมื่อเชื่อมต่อเน็ตสำเร็จ
