# ฝั่งผู้ซื้อ (ซาเล้ง) ลำดับที่ 5: ระบบสื่อสาร (`5. ระบบสื่อสาร`)

  - เชื่อมโยงกับตารางแบ่งฟีเจอร์ฝั่ง **`ผู้ขาย`** ลำดับที่ **`3`** ([`specs/seller/03-buyer-search-and-selection/spec.md`](../../seller/03-buyer-search-and-selection/spec.md)) และลำดับที่ **`8`** ([`specs/seller/08-notifications-and-help/spec.md`](../../seller/08-notifications-and-help/spec.md))

    - **`REQ-SEC-002` / `CC-06`**: คุ้มครองข้อมูลส่วนบุคคล (PDPA) — ปกปิดเบอร์โทรศัพท์และที่อยู่จริงของผู้ขายในสถานะ `S2`
    - **`REQ-UX-001` / `CC-01`**: Mobile-First UI พร้อมปุ่มขนาดใหญ่ `>= 48px` และข้อความด่วนสำเร็จรูป (Quick Replies) อำนวยความสะดวกแก่ซาเล้งที่ไม่ถนัดพิมพ์ (Digital Literacy)
    - **`REQ-OP-001` / `CC-05`**: โหมด Offline Cache ใน Local Storage สำหรับเปิดดูประวัติข้อความและเบอร์โทรที่โหลดไว้แล้วแม้ออฟไลน์
    - **`REQ-SEC-001`**: บันทึก Audit Log ทุกการโทรด่วน การส่งข้อความ และการปิดห้องแชต

## 1. ขอบเขตการทำงาน (Feature Scope)

1. **ระบบแชตข้อความระหว่างซาเล้งและผู้ขาย (`In-App Direct Chatting` — `UC-08`, `AC-B05-01`):**
   - ซาเล้งสามารถเปิดหน้าจอห้องแชตกับผู้ขายตามใบงานได้ตั้งแต่สถานะ **`S2: รอผู้รับซื้อ`** (กรณีผู้ขายส่ง Direct Request มาเจาะจงซาเล้งตาม `AC-S03-04`) จนถึงสถานะ **`S6: รอยืนยันชำระเงิน`**
   - แสดงประวัติข้อความแชตเรียงตามเวลา (Message Feed) แยกฝั่งชัดเจน (ซาเล้งฝั่งขวา / ผู้ขายฝั่งซ้าย) พร้อมเวลาส่งข้อความ (`sent_at`)
   - รองรับการพิมพ์ข้อความอิสระ (Custom Text) ผ่านช่องข้อความที่มีปุ่มส่งขนาดใหญ่ `>= 48px`
2. **แถบข้อความด่วนสำเร็จรูปสำหรับซาเล้ง (`Quick Replies Bar` — `REQ-UX-001`, `AC-B05-02`, `D-B05-03`):**
   - แถบปุ่มลัดข้อความด่วนขนาดใหญ่ (ทัชทาร์เก็ต `>= 48px`) จำนวน 4 ข้อความมาตรฐาน เพื่ออำนวยความสะดวกให้ซาเล้งที่ขับรถหรือผู้สูงอายุที่ไม่ถนัดพิมพ์ข้อความยาว:
     1. 🚚 `"กำลังเดินทางไปครับ"`
     2. 📍 `"ถึงหน้าบ้านแล้วครับ"`
     3. 🚪 `"ช่วยออกมารับหน่อยครับ"`
     4. ⏰ `"ขอเลื่อนเวลาประมาณ 15 นาทีครับ"`
   - เมื่อกดเลือกข้อความด่วน ระบบจะส่งข้อความเข้าห้องแชตทันทีพร้อมบันทึกเวลา
3. **ระบบโทรด่วนผ่านสมาร์ตโฟน (`Native Quick Call Launch` — `UC-08`, `CC-01`, `AC-B05-03`, `D-B05-02`):**
   - มีปุ่ม **"โทรหาผู้ขาย"** (Quick Call) ขนาดใหญ่ `>= 48px` บน Header ของห้องแชตและหน้ารายละเอียดงาน
   - ทำงานโดยเปิดแอปโทรศัพท์พื้นฐานของเครื่องผ่าน URL Scheme มาตรฐาน (`tel:<seller_phone>`)
   - ทำงานร่วมกับระบบบันทึก `audit_logs` (`COLLECTOR_INITIATED_CALL`) เพื่อความโปร่งใส
4. **การคุ้มครองข้อมูลส่วนบุคคลก่อนรับงาน (`Privacy Guard in S2` — `REQ-SEC-002`, `CC-06`, `AC-B05-04`, `D-B05-01`):**
   - ในสถานะ `S2` (Direct Request จากผู้ขาย): ห้องแชตจะแสดงเฉพาะชื่อเรียก (`displayName`) และตำบล/แขวงเท่านั้น โดยระบบจะ **ปิดบังเบอร์โทรศัพท์และซ่อนบ้านเลขที่จริง** จนกว่าซาเล้งจะกดยืนยันรับงานสำเร็จ (`S3`)
   - ปุ่มโทรด่วนจะปิดใช้งาน (Disabled) ในสถานะ `S2` จนกว่างานจะเปลี่ยนเป็น `S3`
5. **การปิดห้องแชตและการคุ้มครองข้อมูลหลังจบงาน (`Post-Transaction Privacy Guard` — `MD-STM-04`, `AC-B05-05`, `D-B05-05`):**
   - เมื่อใบงานเปลี่ยนสถานะเป็น **`S7: สำเร็จ/ปิดงาน`** หรือ **`S8: ยกเลิก`** ระบบจะล็อกห้องแชตเป็น **อ่านได้อย่างเดียว (Read-only)** ทันที
   - ซ่อนปุ่มโทรด่วนและปิดช่องพิมพ์ข้อความ/แถบ Quick Replies พร้อมแสดงป้ายเตือน: *"การทำธุรกรรมสิ้นสุดลงแล้ว ห้องแชตถูกปิดเพื่อความปลอดภัยของข้อมูลส่วนบุคคล"*
6. **การรองรับโหมดออฟไลน์ (`Offline Chat History Cache` — `REQ-OP-001`, `CC-05`, `AC-B05-06`, `D-B05-06`):**
   - แคชประวัติข้อความแชตล่าสุดของงานในคิวลงใน `localStorage` (`saleng_chat_cache_{order_id}`) เพื่อให้ซาเล้งเปิดดูจุดสังเกตหรือข้อความที่ผู้ขายเคยพิมพ์บอกไว้ได้แม้อยู่ในซอยอับสัญญาณ
   - หากไม่มีการเชื่อมต่ออินเทอร์เน็ต (`navigator.onLine === false`): แสดงป้ายแจ้งเตือน *"โหมดออฟไลน์: กำลังแสดงประวัติข้อความจากแคชในเครื่อง"* และปิดการส่งข้อความใหม่พร้อมป้ายเตือนเครือข่าย

## 2. ขอบเขตและสิ่งที่จงใจไม่ทำ (Scope & Non-goals)

> [!IMPORTANT]
> **สิ่งที่ไม่อยู่ในขอบเขตของฟีเจอร์นี้ (Non-goals — `D-B05-02`, `D-B05-04`):**
> 1. **ไม่ทำระบบโทรผ่านอินเทอร์เน็ต (In-App VoIP / WebRTC):** ใช้ Native Phone Dialer (`tel:`) ของอุปกรณ์ เพื่อประหยัด RAM/CPU บนมือถือราคาประหยัดตาม `CC-01`
> 2. **ไม่ทำระบบส่งรูปภาพและไฟล์มีเดียในแชต (Image Upload in Chat):** เพื่อความรวดเร็วและประหยัด Bandwidth ของเครื่องซาเล้ง (รูปถ่ายกองขยะตรวจสอบผ่านหน้ารายละเอียดใบงานได้อยู่แล้ว)
> 3. **ไม่ทำระบบบันทึกและส่งข้อความเสียง (Voice Notes / Audio Clip):** ใช้ข้อความ Quick Replies 4 รูปแบบ หรือการโทรด่วนแทน
> 4. **ไม่เปิดให้ติดต่อกันนอกรอบหลังจบงาน:** ห้องแชตและปุ่มโทรจะปิดทันทีในสถานะ `S7` และ `S8` เพื่อป้องกันการละเมิดสิทธิส่วนบุคคลตาม PDPA
> 5. **ไม่ทำระบบ Push Notification ข้ามเครื่องผ่าน APNs/FCM ภายนอก:** แจ้งเตือนข้อความใหม่ผ่าน In-App Polling / Notification Center

## 5. แบบจำลองข้อมูลและข้อกำหนด UI

### 5.1 โครงสร้างข้อมูลข้อความแชต (`ChatMessage`)
```json
{
  "message_id": "msg-001",
  "order_id": "order-s2-01",
  "sender_id": "saleng-01",
  "sender_role": "COLLECTOR",
  "message_text": "กำลังเดินทางไปครับ",
  "is_quick_reply": true,
  "sent_at": "2026-11-04T10:30:00Z"
}
```

### 5.2 ข้อกำหนดโครงหน้าจอ UI (`data-req="UC-08"`)
- **Header:** แสดงชื่อผู้ขาย, ป้ายสถานะงาน (`S2..S6`), และปุ่มโทรด่วน (`data-testid="quick-call-btn"`, ขนาดความสูง `>= 48px`, ซ่อนใน `S2`, `S7`, `S8`)
- **Chat Feed:** แสดงรายการข้อความแยกสีซาเล้ง (Emerald) และผู้ขาย (Slate)
- **Quick Replies Bar:** แถบปุ่มลัด 4 ปุ่มแบบเลื่อนแนวนอน (`min-h-[48px]`, `data-testid="quick-reply-btn"`)
- **Input Bar:** ช่องพิมพ์ข้อความ (`data-testid="chat-input"`) และปุ่มส่ง (`data-testid="send-message-btn"`, ขนาด `>= 48px`)
