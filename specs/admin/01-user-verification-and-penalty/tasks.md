- **อ้างอิง:** [`specs/admin/01-user-verification-and-penalty/spec.md`](./spec.md) (v2.0), [`specs/admin/01-user-verification-and-penalty/plan.md`](./plan.md) (v1.0), [`specs/000-shared/constraints.md`](../../000-shared/constraints.md)
- **Use Cases หลัก:**
  - `UC-11: ตรวจสอบอนุมัติ KYC และจัดการบทลงโทษผู้ใช้งาน` ([`docs/srs/use-cases.md`](../../../docs/srs/use-cases.md))
- **Use Cases ที่เชื่อมโยง:**
  - `UC-01: ลงทะเบียนและยืนยันตัวตนผู้รับซื้อ (ซาเล้ง)` ([`specs/buyer/01-account-and-kyc/spec.md`](../../buyer/01-account-and-kyc/spec.md)) — ต้นทางส่งเอกสาร KYC
  - `UC-04: จัดการคิวงานและเส้นทางรับซื้อ` ([`specs/002-route/spec.md`](../../002-route/spec.md)) — ตรวจสอบ Precondition Gate (`verified = true` และ `account_status = 'ACTIVE'`)
  - `UC-10` และ `UC-13`: การลงโทษบัญชีผู้ใช้เมื่อพบการร้องเรียน โกงตาชั่ง หรือ No-show ซ้ำซาก
- **Business Rules & State Machine ที่เกี่ยวข้อง:**
  - `D-00-01`: ซาเล้งต้องผ่านการยืนยันตัวตน KYC (`verified = true`) จึงจะสามารถค้นหาและกดรับงานใน `UC-04` ได้
  - `D-A01-03`: สถานะบัญชี 3 ระดับ (`ACTIVE`, `SUSPENDED_TEMPORARY`, `BANNED`)
  - `REQ-SEC-001`: บันทึกประวัติการกระทำลงใน Audit Log (`ADMIN_APPROVED_KYC`, `ADMIN_REJECTED_KYC`, `ADMIN_PENALIZED_USER`, `ADMIN_UNSUSPENDED_USER`)
  - `REQ-SEC-002` / `CC-06`: ปกปิดข้อมูลส่วนบุคคล หมายเลขบัตรประชาชนเป็น `1-1002-XXXXX-XX-X` และเบอร์โทรศัพท์เป็น `08X-XXX-XXXX`
  - `REQ-UX-001` / `CC-01`: ออกแบบ Responsive Web SPA ทัชทาร์เก็ตปุ่มกดขนาดใหญ่ $\ge 48\text{px}$ ทุกปุ่ม
  - `CC-03` / `D-A01-05`: สิทธิ์การเข้าถึง API แอดมินผ่าน `X-Admin-Role: ADMIN` (ส่งกลับ `HTTP 403 Forbidden` หากไม่มีสิทธิ์)
  - `CC-05`: ระบบแอดมินทำงานแบบ Online-only เพื่อความปลอดภัยสูงสุดในการระงับสิทธิ์แบบเรียลไทม์
