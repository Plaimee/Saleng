  - หลักฐานต้นทาง: **`EV-08: ความปลอดภัยและข้อพิพาทหน้างาน ล็อกรูปและหลักฐานห้ามแก้ไข`** ([`docs/srs/evidence.md`](../../../docs/srs/evidence.md)) และ **`EV-09: ข้อกำหนดกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA)`**
  - State Machine กลาง: **`MD-STM-04` สถานะ `S3 (Accepted / On the way)` ถึง `S6 (Payment Pending)`** และสถานะข้อพิพาท **`S8 (Disputed)`** ([`specs/002-route/models.md`](../../002-route/models.md))
  - ความต้องการที่เกี่ยวข้อง:
    - **`UC-09`**: ฟังก์ชันปุ่มฉุกเฉิน SOS และระบบบันทึกหลักฐานเสียง/วิดีโอระหว่างทำธุรกรรม
    - **`REQ-SEC-001`**: บันทึก Audit Log ทุกการกดปุ่ม SOS ฉุกเฉิน และการเริ่ม/หยุดบันทึกหลักฐาน
    - **`REQ-SEC-002`**: ปกปิดเบอร์โทรศัพท์ผู้ติดต่อฉุกเฉินเป็น `08X-XXX-XXXX` ตามมาตรฐาน PDPA
    - **`REQ-QA-001`**: ความเร็วในการส่งสัญญาณแจ้งเหตุ SOS ไปยังศูนย์กลางต้องไม่เกิน `2.0 วินาที` (P95)
    - **`REQ-UX-001`**: ปุ่ม SOS ฉุกเฉินต้องมีขนาดใหญ่ เด่นชัด (`height >= 48px`, สีแดงสะดุดตา) กดได้ทันทีด้วยมือเดียว
    - **`REQ-FN-006`**: ล็อกหลักฐานภาพ/เสียง/วิดีโอ ห้ามแก้ไขหรือลบเมื่อเกิดข้อพิพาท

> [!NOTE]
> **ความสอดคล้องกับสารบัญกลางและสถาปัตยกรรมระบบ (`CC-01`, `CC-02`, `CC-03`):**
> 1. **`CC-01` (Use Case ID):** ปรับรหัส Use Case ให้สอดคล้องกับสารบัญกลางใน [`use-cases.md`](../../../docs/srs/use-cases.md) เป็น **`UC-09: ดูแลความปลอดภัยขณะทำธุรกรรมและปุ่มฉุกเฉิน SOS`** และเชื่อมโยงกับการส่งต่อแจ้งเหตุด่วน/ข้อพิพาทไปยังศูนย์ดูแลระบบ **`UC-13`**
> 2. **`CC-02` (Requirements Catalogue & Evidence):** ปลดรหัส `EV-014` ที่อยู่นอกสารบัญ และเชื่อมโยงกับรหัสหลักฐานกลาง **`EV-08`** (ความปลอดภัยหน้างาน) และ **`EV-09`** (PDPA Masking) พร้อมผูกเข้ากับข้อกำหนด **`REQ-SEC-001`**, **`REQ-SEC-002`**, **`REQ-QA-001`**, **`REQ-UX-001`**, และ **`REQ-FN-006`**
> 3. **`CC-03` (State Machine & Scope):** ปุ่ม **`SOS ฉุกเฉิน`** ใช้งานได้ในสถานะ **`S3..S6`** (ตั้งแต่ซาเล้งกำลังเดินทางมาจนถึงทำธุรกรรมเสร็จ) ส่วนการบันทึกเสียง/วิดีโอหลักฐาน ใช้งานได้ในสถานะหน้างาน **`S4..S6`** โดยไฟล์จะถูกล็อกห้ามลบ/แก้ไขทันทีเมื่อคำขอเปลี่ยนเป็นสถานะ **`S8: Disputed`**

## 1. ขอบเขตการทำงาน (Feature Scope)

1. **ปุ่มแจ้งเหตุด่วน `SOS ฉุกเฉิน` (`Emergency SOS One-Tap Trigger` — `UC-09`, `REQ-UX-001`, `REQ-QA-001`, `Q-02`):**
   - แสดงปุ่ม **`SOS ฉุกเฉิน`** สีแดงสะดุดตา ขนาดใหญ่ไม่น้อยกว่า `48px` (`REQ-UX-001`) บนหน้าจอขณะทำธุรกรรม (`S3`, `S4`, `S5`, `S6`)
   - เมื่อผู้ขายกดปุ่ม `SOS`:
     1. ระบบส่งสัญญาณแจ้งเหตุด่วน (Emergency Alert) ไปยังศูนย์ดูแลระบบ Admin (`UC-13`) ทันที พร้อมพิกัดบ้านผู้ขาย (`geo_point`), ข้อมูลซาเล้ง (`saleng_id`, `saleng_name`, เบอร์โทร), และรหัสคำขอ (`order_id`) ภายในเวลาไม่เกิน `2.0 วินาที` (`REQ-QA-001`)
     2. แสดงหน้าต่างยืนยันการแจ้งเหตุฉุกเฉิน พร้อมปุ่มโทรออกด่วน (`tel:...`) ไปยังเบอร์ผู้ติดต่อฉุกเฉินที่ผู้ขายตั้งค่าไว้ หรือเบอร์ศูนย์ช่วยเหลือ Saleng Hotline (`02-123-4567`) หรือ 191
     3. บันทึกประวัติการกด SOS ลงใน `AuditLog` (`REQ-SEC-001`)

2. **การบันทึกเสียงและวิดีโอหลักฐานระหว่างทำธุรกรรม (`In-Transaction Media Evidence Recording` — `UC-09`, `Q-01`):**
   - ผู้ขายสามารถกดเริ่มและหยุดบันทึกเสียงหรือคลิปวิดีโอจากหน้าจอทำธุรกรรมหน้างาน (`S4..S6`)
   - แสดงตัวจับเวลาการบันทึก (Recording Timer), สัญญาณคลื่นเสียง (Waveform indicator), และปุ่มหยุดบันทึก
   - จำกัดขนาดไฟล์หลักฐานไม่เกิน `25 MB` ต่อไฟล์ เพื่อประสิทธิภาพตามข้อกำหนด `CC-01`
   - แนบไฟล์หลักฐานเข้ากับรหัสคำขอ (`order_id`) พร้อมเวลาประทับ (Timestamp) และขนาดไฟล์
   - บันทึก Audit Log ทุกครั้งที่มีการเริ่มและหยุดบันทึกหลักฐาน (`REQ-SEC-001`)

3. **การตั้งค่าเบอร์ผู้ติดต่อฉุกเฉินที่ไว้ใจได้ (`Trusted Emergency Contact Settings` — `UC-09`, `REQ-SEC-002`, `Q-03`):**
   - ผู้ขายสามารถตั้งค่าข้อมูลผู้ติดต่อฉุกเฉินที่ไว้ใจได้: ชื่อผู้ติดต่อ, ความสัมพันธ์ (เช่น บุตรหลาน/ญาติ), และเบอร์โทรศัพท์
   - มีการแสดงผลเบอร์โทรศัพท์แบบ PDPA Masking `08X-XXX-XXXX` เสมอ (`REQ-SEC-002`)
   - หากผู้ขายยังไม่ได้ระบุเบอร์ญาติ ระบบจะกำหนดค่าเริ่มต้น (Default) เป็นศูนย์ช่วยเหลือ Saleng Call Center (`02-123-4567`)

4. **การล็อกหลักฐานเมื่อเกิดเหตุฉุกเฉินหรือข้อพิพาท (`Evidence Lock & Dispute Integration` — `REQ-FN-006`, `UC-13`, `Q-04`):**
   - เมื่อใบงานมีการกด SOS หรือเปลี่ยนสถานะเป็น **`S8: Disputed`** ไฟล์บันทึกเสียง/วิดีโอทั้งหมดจะถูกเปลี่ยนสถานะเป็น "ห้ามลบ/ห้ามแก้ไข (Read-only / Immutable)" ตามหลักการของ `REQ-FN-006`
   - ข้อมูลหลักฐานและประวัติการกดแจ้งเหตุทั้งหมดจะถูกส่งต่อไปยังศูนย์จัดการข้อพิพาทของ Admin ใน `UC-13` ทันที

> [!NOTE]
> **ขอบเขตและสิ่งที่จงใจไม่ทำ (Non-goals — `Q-05`):**
> 1. **ไม่ทำระบบดักฟังหรือบันทึกเสียงอัตโนมัติด้วย AI (No automatic audio surveillance / keyword trigger):** เพื่อเคารพสิทธิความเป็นส่วนตัว (PDPA) ให้ผู้ขายเป็นผู้กดเริ่ม/หยุดด้วยตนเอง (Manual Trigger)
> 2. **ไม่ทำระบบโทรศัพท์ผ่านอินเทอร์เน็ตภายในแอป (No in-app VoIP engine):** ให้ใช้ `tel:` protocol ของอุปกรณ์มือถือเพื่อโทรออกผ่านเครือข่ายโทรศัพท์ปกติ
> 3. **ไม่เชื่อมโยง API ไปยังศูนย์วิทยุตำรวจ 191 โดยตรง:** โดยส่งข้อมูลเข้าศูนย์ดูแลระบบ Admin ของแพลตฟอร์ม และมีปุ่มโทรออกฉุกเฉินบนมือถือ

## 2. เกณฑ์การยอมรับ (`Acceptance Criteria`)

- **`AC-S09-01` (In-Transaction Audio/Video Evidence Recording — `UC-09`, `Q-01`):**
  - ในสถานะหน้างาน (`S4..S6`) ผู้ขายสามารถกดเริ่มและหยุดบันทึกเสียงหรือคลิปวิดีโอเพื่อแนบเป็นหลักฐานคู่กับ `order_id` ได้ พร้อมแสดงตัวจับเวลาและจำกัดขนาดไม่เกิน 25 MB
- **`AC-S09-02` (Emergency SOS One-Tap Trigger & Dispatch — `UC-09`, `REQ-UX-001`, `REQ-QA-001`, `Q-02`):**
  - ในสถานะ `S3..S6` แสดงปุ่ม `SOS ฉุกเฉิน` ขนาดไม่น้อยกว่า 48px และเมื่อกด ระบบจะส่งพิกัดและข้อมูลซาเล้งไปยังศูนย์ดูแลระบบภายใน 2.0 วินาที พร้อมแสดงปุ่มต่อสายด่วนโทรออกได้ทันที
- **`AC-S09-03` (Trusted Emergency Contact Management & Masking — `UC-09`, `REQ-SEC-002`, `Q-03`):**
  - ผู้ขายสามารถบันทึกและแก้ไขข้อมูลผู้ติดต่อฉุกเฉินได้ โดยเบอร์โทรศัพท์ต้องถูกปกปิดเป็น `08X-XXX-XXXX` ตามมาตรฐาน PDPA และมีเบอร์ศูนย์ช่วยเหลือ Saleng เป็นค่าเริ่มต้น
- **`AC-S09-04` (Evidence Immutability on Dispute / SOS — `REQ-FN-006`, `UC-13`, `Q-04`):**
  - เมื่อมีการกด SOS หรือใบงานเข้าสู่สถานะ `S8: Disputed` ไฟล์หลักฐานเสียง/วิดีโอจะถูกล็อกห้ามลบและส่งต่อให้ศูนย์จัดการข้อพิพาท Admin (`UC-13`) ทันที
- **`AC-S09-05` (Security Audit Logging for Safety Events — `REQ-SEC-001`):**
  - ทุกการกดปุ่ม SOS ฉุกเฉิน และการเริ่ม/หยุดบันทึกหลักฐาน ต้องบันทึก Audit Log พร้อมเวลาและรหัสผู้กระทำอย่างครบถ้วน
