  - แผนผังสถานะคำขอรับซื้อ: **`MD-STM-04` สถานะ `S1` ถึง `S9` และ Events `E1..E11`** ([`specs/000-shared/constraints.md`](../../000-shared/constraints.md), [`specs/002-route/models.md`](../../002-route/models.md))

  - เงื่อนไขก่อนหน้า (Preconditions):
    1. ผู้ขายมีบัญชีและที่อยู่นัดหมายเริ่มต้นจาก **`UC-01`**
    2. มีรายการของเก่าและราคาประเมินเบื้องต้นในสถานะฉบับร่าง **`UC-02`** (`S1 Draft`)
  - ความต้องการที่เกี่ยวข้อง:
    - **`UC-04`**: จัดการคิวงาน คำนวณเส้นทางรับซื้อ และติดตามสถานะการเดินทาง
    - **`REQ-FN-003`**: ควบคุมการเปลี่ยนสถานะคำขอรับซื้อตามผังสถานะ `S1..S9`
    - **`REQ-SEC-001`**: บันทึก Audit Log ทุกการเปลี่ยนสถานะและการยกเลิกคำขอ
    - **`REQ-SEC-002`**: ซ่อนบ้านเลขที่และพิกัดละเอียดของผู้ขายก่อนเกิดธุรกรรม
    - **`REQ-UX-001`**: ปุ่มดำเนินการหลักและการล็อกปุ่มยกเลิกชัดเจนตามเกณฑ์
    - **`REQ-QA-001`**: การอัปเดตและแสดงผลสถานะที่แม่นยำรวดเร็ว
    - **`CC-01..CC-06`**, **`D-00-01..D-00-03`**
    - **`EV-01`**, **`EV-02`**, **`EV-08`**: หลักฐานการสำรวจความต้องการ ([`docs/srs/evidence.md`](../../../docs/srs/evidence.md))

> [!NOTE]
> **ความสอดคล้องกับสารบัญกลางและสถาปัตยกรรมระบบ (`CC-01`, `CC-02`, `CC-03`):**
> 1. **`CC-01` (Use Case Alignment):** ปรับแก้รหัส Use Case จากร่างเดิมที่เป็น `UC-07` (ซึ่งเป็นระบบชำระเงินในสารบัญกลาง) ให้สอดคล้องกับสารบัญหลักของระบบเป็น **`UC-04: จัดการคิวงาน คำนวณเส้นทางรับซื้อ และติดตามสถานะการเดินทาง`** (ฟังก์ชันฝั่งผู้ขาย: การนัดหมาย, ส่งคำขอ, ติดตามสถานะ, และการยกเลิก) ร่วมกับแผนภาพสถานะ **`MD-STM-04`**
> 2. **`CC-02` (Requirements Catalogue & Evidence Mapping):** ปลดรหัส `EV-012` ที่อยู่นอกสารบัญ และเชื่อมโยงรหัสหลักฐานกลาง **`EV-01`** (การนัดหมายและข้อจำกัดหน้างาน), **`EV-02`** (การติดตามสถานะในเส้นทาง), และ **`EV-08`** (ความปลอดภัยและการคุ้มครองข้อมูล) พร้อมทั้งผูกรหัสความต้องการกลาง **`REQ-FN-003`**, **`REQ-SEC-001`**, **`REQ-SEC-002`**, และกฎธุรกิจ **`BR-03`** ครบถ้วน
> 3. **`CC-03` (State Machine & Cancellation Guard `BR-03`):** ผู้ขายสามารถกดยกเลิกนัดหมายได้ในสถานะ **`S1 (Draft)`**, **`S2 (Pending/Open)`**, และ **`S3 (Assigned/Accepted)`** โดยคำขอจะเปลี่ยนเป็นสถานะ **`S8 (Cancelled)`** แต่เมื่อซาเล้งกดยืนยันเริ่มออกเดินทางเข้าสู่สถานะ **`S4 (In-Transit)`** ระบบจะล็อกปุ่มยกเลิกบนหน้าจอทันที และบล็อกการยกเลิกผ่าน API (HTTP 400 ตามกฎ `BR-03`)

## 1. ขอบเขตการทำงาน (Feature Scope)

1. **เลือกวันเวลานัดหมายและยืนยันส่งคำขอ (`Booking Slot Selection & S1 -> S2 Transition` — `REQ-FN-003`, `AC-S05-01`, `Q-01`):**
   - ผู้ขายสามารถเลือกช่วงเวลานัดหมายได้ 2 รูปแบบ:
     1. **เรียกทันที (ด่วนใน 1–2 ชม.)**: สำหรับผู้ขายที่พร้อมส่งมอบของเก่าทันที
     2. **นัดหมายล่วงหน้า**: ระบุวันที่ และเลือกช่วงเวลามาตรฐาน 3 ช่วง (ช่วงเช้า 09:00–12:00 น., ช่วงบ่าย 13:00–16:00 น., ช่วงเย็น 16:00–18:00 น.)
   - เมื่อกดยืนยันนัดหมาย คำขอจะเปลี่ยนสถานะจาก `S1 (Draft)` เป็น `S2 (Pending / Open)` และบันทึก Audit Log `ORDER_SUBMITTED`
2. **ติดตามสถานะคำขอรับซื้อแบบเรียลไทม์ 9 สถานะ (`Real-Time Status Tracking` — `MD-STM-04`, `REQ-FN-003`, `AC-S05-02`):**
   - ผู้ขายสามารถเปิดดูหน้าจอติดตามสถานะคำขอ พร้อม Stepper แสดงความคืบหน้าของใบงาน:
     - `S1: ฉบับร่าง (Draft)`
     - `S2: รอผู้รับซื้อ (Pending / Open)`
     - `S3: มีผู้รับงานแล้ว (Assigned / Accepted)` — แสดงการ์ดข้อมูลซาเล้งที่รับงาน (ชื่อ, รูปถ่าย, ป้าย KYC 100%, ทะเบียน/ประเภทยานพาหนะ)
     - `S4: กำลังเดินทาง (In-Transit)` — แสดงระยะทางที่เหลือ และเวลาประเมินถึงหน้างาน (ETA)
     - `S5: ถึงจุดนัดหมายและชั่งของ (Arrived & Weighed)` — แจ้งเตือนว่าซาเล้งถึงหน้าบ้านแล้ว
     - `S6: รอยืนยันชำระเงิน (Pending Payment)`
     - `S7: สำเร็จ / ปิดงาน (Completed)`
     - `S8: ยกเลิก (Cancelled)`
     - `S9: ระงับชั่วคราว / ข้อพิพาท (Disputed / Frozen)`
3. **การบังคับใช้กฎเหล็กการยกเลิกนัดหมายของผู้ขาย (`Pre-Transit Cancellation Guard` — `BR-03`, `AC-S05-03`, `Q-02`):**
   - ผู้ขายสามารถกดยกเลิกนัดหมายได้ในสถานะ `S1`, `S2`, และ `S3` โดยระบุเหตุผลการยกเลิก และสถานะจะเปลี่ยนเป็น `S8 (Cancelled)` พร้อม Audit Log `ORDER_CANCELLED_BY_SELLER`
   - **กฎเหล็ก `BR-03`:** เมื่อซาเล้งกดยืนยันเริ่มออกเดินทางเข้าสู่สถานะ **`S4 (กำลังเดินทาง / In-Transit)`** ระบบจะ **ล็อกปุ่มยกเลิก (Disabled)** ทันที และ API จะปฏิเสธคำขอยกเลิกจากผู้ขาย (HTTP 400: *"ไม่สามารถยกเลิกนัดหมายได้เนื่องจากซาเล้งกำลังเดินทางมายังหน้างานแล้วตามกฎ BR-03"*)
4. **การแจ้งเตือนความคืบหน้าสถานะคำขอ (`Status Progress Notifications` — `AC-S05-04`, `Q-04`):**
   - ส่งการแจ้งเตือน In-App Banner เมื่อซาเล้งกดรับงาน (`S2 -> S3`), เมื่อซาเล้งเริ่มออกเดินทาง (`S3 -> S4`), และเมื่อซาเล้งเดินทางถึงหน้างาน (`S4 -> S5`)
5. **การดูสรุปรายละเอียดนัดหมายและข้อมูลติดต่อ (`Booking Summary & Contact Access` — `REQ-SEC-002`, `AC-S05-05`):**
   - แสดงสรุปรายการของเก่าในคำขอ, ที่อยู่นัดหมาย, ปุ่มโทรด่วนหาซาเล้งที่รับงาน, และปุ่มเปิดห้องแชต

> [!NOTE]
> **ขอบเขตและสิ่งที่จงใจไม่ทำ (Non-goals — `Q-05`):**
> 1. **ไม่ทำแผนที่สดแบบ Real-time GPS Animation ขยับทุกวินาที:** ใช้การอัปเดตระยะทางและเวลาถึงหน้างาน (ETA) ตามรอบพิกัด GPS ซาเล้งทุก 60 วินาทีตาม `CC-02` เพื่อประหยัดพลังงานและแรมของอุปกรณ์ตาม `CC-01`
> 2. **ไม่คิดค่าปรับกรณีผู้ขายยกเลิกก่อนออกเดินทาง:** ให้เป็นบริการฟรีตามกฎธุรกิจ `BR-03`
> 3. **ไม่อนุญาตให้แก้ไขรายการของเก่าหลังจากซาเล้งกดรับงาน (`S3`) แล้ว:** หากต้องการแก้ไข ให้กดยกเลิกตามกฎ `BR-03` แล้วสร้างคำขอใหม่

## 2. เกณฑ์การยอมรับ (`Acceptance Criteria`)

- **`AC-S05-01` (Booking Slot & Order Submission — `REQ-FN-003`, `Q-01`):** ผู้ขายสามารถเลือกช่วงเวลานัดหมาย (เรียกทันที หรือระบุวัน/ช่วงเวลาล่วงหน้า) และคำขอต้องเปลี่ยนสถานะจาก `S1 (Draft)` เป็น `S2 (Pending / Open)`
- **`AC-S05-02` (Real-Time 9-State Timeline Stepper — `MD-STM-04`, `REQ-FN-003`):** หน้าจอติดตามสถานะต้องแสดงขั้นตอนความคืบหน้าของคำขอได้อย่างถูกต้องตามผังสถานะ `S1` ถึง `S9`
- **`AC-S05-03` (Pre-Transit Cancellation Enforcement — `BR-03`, `Q-02`):** ผู้ขายสามารถกดยกเลิกคำขอได้ในสถานะ `S1..S3` (`-> S8: ยกเลิก`) แต่เมื่อคำขอเข้าสู่สถานะ `S4 (กำลังเดินทาง)` ระบบต้องล็อกปุ่มยกเลิก และบล็อกการยกเลิกผ่าน API ทันที
- **`AC-S05-04` (In-Transit ETA & Distance Display — `CC-02`, `Q-03`):** ในสถานะ `S4` ผู้ขายต้องเห็นระยะทางที่เหลือและเวลาประเมินถึงหน้างาน (ETA) ที่อัปเดตตามพิกัด GPS ซาเล้ง
- **`AC-S05-05` (Audit Logging for Booking & Cancellation — `REQ-SEC-001`):** ทุกการส่งคำขอนัดหมาย การเปลี่ยนสถานะ และการยกเลิก ต้องถูกบันทึกลงในตาราง `AuditLog` แบบ Append-only
