# ฝั่งผู้ขาย ลำดับที่ 6: ระบบชำระเงินและตรวจสอบ (`6. ระบบชำระเงินและตรวจสอบ`)

- **Version:** `2.0` | **Status:** `reviewed-post-clarify` | **Owner:** กลุ่ม 2 (แพลตฟอร์มรับซื้อของเก่า/ซาเล้ง)
- **อ้างอิงอาร์ติแฟกต์ที่เกี่ยวข้อง:**
  - ตารางแบ่งฟีเจอร์ฝั่ง **`ผู้ขาย`** ลำดับที่ **`6`**
  - สารบัญ Use Cases ระบบกลาง: **`UC-06: ยืนยันหรือปฏิเสธผลชั่งจริง/ราคาใหม่`** และ **`UC-07: ชำระเงิน ออกใบเสร็จดิจิทัล และซิงก์ข้อมูล`** ([`docs/srs/use-cases.md`](../../../docs/srs/use-cases.md))
  - In Scope: **`SC-03: การบันทึกสรุปน้ำหนัก รายการขยะ และยอดเงินหลังการซื้อขายเสร็จสิ้น`**
  - State Machine กลาง: **`MD-STM-04` สถานะ `S4 (Weighing)` -> `S5 (Re-Quote / Weight Confirmed)` -> `S6 (Settled / Pending Payment)` -> `S7 (Completed)` และ `S8 (Disputed)`** ([`specs/002-route/models.md`](../../002-route/models.md))
  - ความต้องการที่เกี่ยวข้อง:
    - **`REQ-FN-004`**: ผู้ขายตรวจสอบและยืนยันน้ำหนักชั่งจริงก่อนสรุปยอดเงิน (บล็อก 100% หากยังไม่กดยืนยัน)
    - **`REQ-FN-005`**: สร้างใบเสร็จดิจิทัล (`DigitalReceipt`) รหัสอ้างอิงไม่ซ้ำ น้ำหนักชั่งจริง ราคาล็อกต่อหน่วย และยอดชำระสุทธิ
    - **`REQ-FN-006`**: เปลี่ยนสถานะเป็น `S8: ข้อพิพาท (Disputed)` เมื่อผู้ขายปฏิเสธผลชั่ง พร้อมล็อกภาพถ่ายหน้าตาชั่งส่งแอดมิน
    - **`REQ-BR-002`**: ใช้ราคาต่อหน่วยที่ล็อกไว้ตอนนัดหมาย (`locked_unit_price`) มาคำนวณยอดชำระสุทธิ (`actual_weight * locked_unit_price`)
    - **`REQ-SEC-001`**: บันทึกประวัติการเปลี่ยนสถานะใบงานลงในตาราง Audit Log
    - **`REQ-SEC-002`**: ปกปิดเบอร์โทรศัพท์บนใบเสร็จดิจิทัลเป็น `08X-XXX-XXXX`

> [!NOTE]
> **ความสอดคล้องกับสารบัญกลางและสถาปัตยกรรมระบบ (`CC-01`, `CC-02`, `CC-03`):**
> 1. ปรับรหัส Requirement ให้สอดคล้องกับ Catalogue กลาง ([`catalogue.md`](../../../docs/srs/catalogue.md)) โดยใช้ `REQ-FN-004` สำหรับการตรวจสอบ/ยืนยันน้ำหนัก และ `REQ-FN-005` สำหรับการออกใบเสร็จดิจิทัล
> 2. ปรับรหัส Use Case ให้ตรงกับสารบัญกลางใน [`use-cases.md`](../../../docs/srs/use-cases.md) คือ `UC-06` (ยืนยันผลชั่งจริง) และ `UC-07` (ชำระเงินและออกใบเสร็จดิจิทัล)
> 3. ผังสถานะยึดตาม `MD-STM-04` อย่างเคร่งครัด (`S4 -> S5 -> S6 -> S7` และทางเลือกข้อพิพาท `S8`)

## 1. ขอบเขตการทำงาน (Feature Scope)

1. **ตรวจสอบและกดยืนยันตัวเลขน้ำหนักชั่งจริงหน้างาน (Seller Confirmation Gate 100% — `REQ-FN-004`, `Q-01`):**
   - เมื่อซาเล้งเดินทางถึงจุดนัดหมายและชั่งของหน้างาน (`S4: ถึงจุดนัดหมายและชั่งของ`) และกรอกค่าน้ำหนักชั่งจริงแยกตามชนิดวัสดุ (`actual_weight_kg` หรือจำนวนกระสอบ)
   - ข้อมูลผลชั่งจริงพร้อมรูปถ่ายหน้าตาชั่งจะแสดงบนหน้าจอของผู้ขายแบบเรียลไทม์
   - **กฎเหล็ก (`REQ-FN-004`, `Q-01`):** ผู้ขายต้องตรวจสอบตัวเลขน้ำหนักบนหน้าจอของตนเองและ **กดยืนยันตัวเลขน้ำหนัก (100% Confirmation Gate)** ระบบจึงจะอนุญาตให้เปลี่ยนสถานะเข้าสู่ `S6: รอยืนยันชำระเงิน (Pending Payment)`
   - หากผู้ขายยังไม่ได้กดยืนยัน ระบบต้องบล็อกไม่ให้ไปยังขั้นตอนการชำระเงิน `100%`

2. **ทางเลือกกรณีผลชั่งไม่ถูกต้อง / ขอให้ชั่งซ้ำ หรือ แจ้งข้อพิพาท (`REQ-FN-006`, `Q-02`):**
   - ในหน้าจอตรวจสอบผลชั่ง หากผู้ขายพบว่าตัวเลขน้ำหนักหรือชนิดวัสดุไม่ถูกต้อง ผู้ขายสามารถเลือก:
     - **`"ขอให้ชั่งซ้ำ"`:** ส่งสัญญาณแจ้งเตือนไปยังหน้าจอซาเล้งให้ตรวจสอบตาชั่งและกรอกค่าน้ำหนักใหม่ในสถานะ `S4`
     - **`"ปฏิเสธผลชั่ง / แจ้งข้อพิพาท"`:** ระบบเปลี่ยนสถานะใบงานเป็น **`S8: ข้อพิพาท (Disputed)`** ตาม `REQ-FN-006` พร้อมล็อกภาพถ่ายหน้าตาชั่งดิจิทัล พิกัด GPS และราคาที่ล็อกไว้ เพื่อส่งให้ผู้ดูแลระบบ (Admin) ตรวจสอบและตัดสินข้อพิพาทต่อไป

3. **เลือกช่องทางรับเงินและกดยืนยันรับเงิน (Payment Confirmation Flow — `UC-07`, `Q-03`):**
   - เมื่อผ่านการยืนยันน้ำหนัก (`S5 -> S6: รอยืนยันชำระเงิน`) ระบบคำนวณยอดเงินสุทธิจาก:
     $$\text{ยอดชำระสุทธิ} = \sum (\text{actual\_weight} \times \text{locked\_unit\_price})$$
     โดยใช้ราคาที่ล็อกไว้ตอนนัดหมาย (`REQ-BR-002`) เป็นตัวคูณ
   - ผู้ขายสามารถเลือกช่องทางการรับเงิน:
     - **`เงินสด (Cash)`:** ซาเล้งส่งมอบเงินสดหน้างาน เมื่อผู้ขายได้รับครบถ้วน ผู้ขายกดปุ่ม *"ได้รับเงินสดเรียบร้อย"*
     - **`PromptPay QR Code`:** ผู้ขายแสดง QR Code PromptPay ของตนเองให้ซาเล้งสแกนโอนเงิน เมื่อเงินเข้าบัญชีเรียบร้อย ผู้ขายกดปุ่ม *"ได้รับเงินโอนเรียบร้อย"*
   - **ความปลอดภัยสูงสุด (`Q-03`):** การเปลี่ยนสถานะใบงานเป็น **`S7: สำเร็จ / ปิดงาน (Completed)`** จะเกิดขึ้นเมื่อ **ผู้ขายเป็นผู้กดยืนยันรับเงินบนหน้าจอของตนเอง** เท่านั้น

4. **ออกใบเสร็จดิจิทัลสรุปรายการซื้อขาย (`REQ-FN-005`, `SC-03`, `Q-04`):**
   - เมื่อสถานะเปลี่ยนเป็น `S7 (Completed)` ระบบสร้างใบเสร็จดิจิทัล (`DigitalReceipt`) โดยอัตโนมัติให้ทั้งสองฝ่าย ประกอบด้วย:
     1. รหัสใบเสร็จอ้างอิงไม่ซ้ำ (เช่น `REC-YYYYMMDD-XXXX`)
     2. วันที่และเวลาที่ทำรายการสำเร็จ
     3. ข้อมูลผู้ขายและซาเล้ง (ปิดบังเบอร์โทรศัพท์ตาม `REQ-SEC-002` เช่น `08X-XXX-1234`)
     4. รายการของเก่า: หมวดหมู่วัสดุ, น้ำหนักชั่งจริง (`กก.` หรือ `กระสอบ`), ราคาต่อหน่วยที่ล็อกไว้ (`locked_unit_price`), ยอดเงินรวมแต่ละรายการ
     5. ยอดเงินสุทธิรวม (บาท)
     6. ช่องทางชำระเงินที่ใช้ (`เงินสด` หรือ `PromptPay`)
     7. ปุ่มบันทึกเป็นรูปภาพ / ดาวน์โหลดใบเสร็จ

> [!NOTE]
> **ขอบเขตและสิ่งที่จงใจไม่ทำ (Non-goals — `Q-05`):**
> 1. **ไม่ทำระบบกระเป๋าเงินดิจิทัล (In-App Wallet) หรือ Payment Gateway ตัดบัตรเครดิต:** การชำระเงินใช้เงินสดหน้างาน หรือเปิดแอปธนาคารสแกน PromptPay ภายนอกเท่านั้น
> 2. **ไม่รวมระบบรีวิวและให้คะแนนหลังจบงาน (`UC-10`):** ตัดไปอยู่ใน [`specs/seller/07-post-transaction/`](../07-post-transaction/spec.md) ตามผัง Use Case สากล

## 2. เกณฑ์การยอมรับ (`Acceptance Criteria`)

- **`AC-S06-01` (100% Seller Weight Confirmation Gate — `REQ-FN-004`, `Q-01`):**
  - เมื่อซาเล้งกรอกน้ำหนักชั่งจริงในสถานะ `S4` ข้อมูลผลชั่งต้องแสดงบนหน้าจอของผู้ขาย และระบบต้องบล็อกไม่ให้ออกใบสรุปยอดเงินหรือข้ามไปขั้นตอนชำระเงิน 100% จนกว่าผู้ขายจะกดปุ่ม *"ยืนยันตัวเลขน้ำหนัก"* (`S5 -> S6`)
- **`AC-S06-02` (Dispute & Re-Weigh Option — `REQ-FN-006`, `Q-02`):**
  - ในหน้าจอยืนยันน้ำหนัก หากผู้ขายไม่เห็นด้วย ผู้ขายสามารถกด *"ขอให้ชั่งซ้ำ"* (ส่งกลับไปให้ซาเล้งแก้ค่าน้ำหนัก) หรือกด *"ปฏิเสธผลชั่ง / แจ้งข้อพิพาท"* ซึ่งระบบจะเปลี่ยนสถานะเป็น `S8: Disputed` ทันทีพร้อมล็อกภาพตาชั่งและส่งต่อให้แอดมิน
- **`AC-S06-03` (Payment Method Selection & Seller Cash/PromptPay Confirmation — `UC-07`, `Q-03`):**
  - ในสถานะ `S6` ผู้ขายสามารถเลือกรับชำระด้วย `"เงินสด"` หรือ `"PromptPay QR Code"` และเมื่อได้รับเงินจริง ผู้ขายกดยืนยันรับเงินบนหน้าจอของตนเอง คำขอจึงจะเปลี่ยนสถานะเข้าสู่ `S7: สำเร็จ / ปิดงาน (Completed)`
- **`AC-S06-04` (Digital Receipt Generation & PII Masking — `REQ-FN-005`, `REQ-SEC-002`, `Q-04`):**
  - เมื่อคำขอเปลี่ยนเป็น `S7` ระบบต้องสร้างใบเสร็จดิจิทัล (`DigitalReceipt`) ทันที โดยมีรหัสใบเสร็จไม่ซ้ำ แสดงรายการวัสดุ น้ำหนักจริง ราคาต่อหน่วยที่ล็อกไว้ ยอดรวมสุทธิ ช่องทางชำระเงิน และปกปิดเบอร์โทรศัพท์เป็น `08X-XXX-XXXX`
- **`AC-S06-05` (Audit Log & State Transition Integrity — `REQ-SEC-001`, `CC-03`):**
  - ทุกการเปลี่ยนสถานะจาก `S4 -> S5 -> S6 -> S7` (หรือ `S5 -> S8`) ต้องบันทึกประวัติการกระทำ เวลา และรหัสผู้ดำเนินการลงใน Audit Log ตรวจสอบย้อนกลับได้
